# Day 1 — bootstrapping langGUI

I've been recently playing with openclaw. I was so into the capability and the
integrations — all those tools, all those connectors — that I kept piling
things on. But in reality I only need a handful of them. It's too complex
to my liking. So I thought: maybe I can build a lightweight LangGraph GUI,
multiple agents for different tasks, each with its own instructions and
its own model. And here we go — **langGUI**, my small project to replace
my openclaw setup.

The mental model is dead simple: agents are recipes (model + system prompt
+ tools), threads are conversations, and the runtime is LangGraph with a
SQLite checkpoint so I can close the tab and come back later. Everything
lives under `~/.langgui` on the local box. No cloud, no telemetry, no
"sign in with X" — just me on my laptop talking to whichever model is best
for the task.

## What I got working

**Day 1: 31 commits.** Not pretty, not cohesive — this is the "throw the
walls up and check they hold" day.

The core loop landed first: Next.js App Router + a LangGraph agent
runtime + a SQLite checkpointer. Then I bolted on the obvious chrome:
a chat view, an agent selector, a message bubble that renders markdown,
streaming via WebSocket (and a fallback over SSE because mobile drops
the WS the moment the screen sleeps).

A few things I knew I'd want from day one:

- **Multiple providers, one agent shape.** Anthropic, OpenAI, Gemini,
  GitHub Copilot, DeepSeek — agents just pick a `provider + model` pair.
  Most of the day's "Copilot fix" commits were me untangling GitHub's
  three different auth flavors (OAuth device-flow vs personal access
  tokens vs Models API tokens). It is more painful than it should be.
- **Background work.** A scheduler that wakes on SSE subscribe so a
  cron-driven agent can ping me when something happens. Teams-style
  in-app toasts for the result, click-to-jump straight to the thread.
- **Don't lose what's in flight.** Auto-scroll only when content
  actually grows (not on every re-render). A queue so messages typed
  during streaming get drained as part of the same turn, not lost.
- **Identity.** Wired Tailscale identity passthrough so when I open
  this from my phone over the tailnet, the server already knows it's me.
  Loopback gets a free pass for local dev.
- **Auto-start on Windows.** A scheduled-task installer so the box
  boots, logs in, and the app is already there.

A few rough edges I left for tomorrow-me: the early Copilot commits
have plain English subject lines ("Fix this", "Handle that") — no
`type(scope):` prefix. I hadn't fully committed to Conventional
Commits yet on day 1. Past-me, learn to type a colon.

## What I learned

- **Streaming is the easy part. Reconnection is the hard part.** Got
  the happy path live in an hour. Spent the rest of the day on the
  cases where the socket dies mid-token.
- **Scheduler + SSE + globalThis-pinned singletons is a real trap on
  Next.** Lost an hour to the scheduler getting collected because a
  module reload created a second instance. Pin it to `globalThis` and
  move on. (See [66cebcf](../../#) — `fix(runtime): pin notification
  bus + scheduler state to globalThis`.)
- **GitHub Copilot's API surface is not one API.** Device-flow token,
  PAT, and the Models registry are three doors that look like one.

That's enough for a day. Tomorrow: tools.
