# 2026-05-20 -- Day 6

Today felt less like "building a feature" and more like sweeping up all
the places where the app could still embarrass me in real life. Jarela is
already useful. The work today was about making it dependable when the
network is annoying, the UI is cramped, or I come back to it later and
expect it to behave.

**45 commits.** Most of them were not glamorous. They were the kind of
changes that make the rest of the project easier to trust.

## What changed

### Proxy setup stopped being folklore

One of the biggest shifts was taking proxy configuration out of the
"set this env var somewhere and hope you remember it" bucket.

Now it is a real part of the app:

- There is an API for proxy config (`GET/PUT/DELETE /api/v1/proxy-config`).
- The settings are stored encrypted and applied at runtime.
- The UI has an explicit Network section instead of a hidden back door.
- HTTPS proxies and custom CA bundles are supported too.

That matters because the app should not silently fall over just because a
machine sits behind stricter network rules. I wanted a clear answer to
"how does this box reach the internet?" and now it has one.

### The setup flow finally feels like a setup flow

The onboarding path now walks through integration manifests instead of
dropping the user into a blank shell. It feels less like "here is an empty
project, good luck" and more like "here is the right starting point, go
from here."

### Releases are less awkward to ship

The distribution side got cleaned up at the same time:

- Portable archives per OS.
- An npm package path.
- A tidier Mac install script.
- A less painful Tailscale serve recipe.

The practical win is small but real: fewer install notes, fewer "which
script do I run" moments, fewer opportunities to confuse myself later.

### Streaming got a cleaner lifecycle

`feat(streaming)!` split run submission from event subscription using
EventSource.

That sounds technical because it is, but the effect is simple: submit a run
explicitly, subscribe separately, and stop pretending those are the same
thing. It makes reconnects easier to reason about and removes some hidden
coupling in the flow.

### Extensibility opened up

I also spent time widening the surface area for integrations:

- Online discovery from the official MCP Registry.
- Hot-loading for external providers and tools.
- Native GitHub REST tools.
- Environment sync from shell rc files and the Windows registry.

The pattern is the part I care about: less code surgery, more configuration,
and fewer excuses for why a capability has to live inside the repo forever.

### The visible polish pass

The other big chunk of the day was UI cleanup. These are the sorts of
changes nobody asks for by name, but everybody feels when they are wrong:

- Liquid-glass redesign and input-bar alignment cleanup.
- Slash command autocomplete and a slimmer placeholder.
- Topbar positioning fixes and safe-area cleanup.
- Dark-mode logo legibility fix.
- Menu tray and icon sizing improvements.
- In-app deep links and URL sync.
- PWA reload-loop and overlay behavior fixes.

None of that is headline material. All of it makes the app feel less
fragile.

## Notes from the edges

- The Outlook setup guide now points at the correct Azure blade.
- Calendar scope handling now works consistently.
- Tailscale serve helpers are more PowerShell 5.1 friendly and proxy to
  the right backend protocol.
- The launchctl install path now uses the modern bootout/bootstrap flow.

## What I learned

- Config that only exists in env vars is really just hidden debt.
- Streaming gets easier to think about when submit and subscribe are
  separate actions.
- Stability work is usually a pile of tiny fixes, not one grand rewrite.
- Discovery, hot-loading, and docs need to ship together if extensibility
  is supposed to matter.

Day 6 was quieter than the first few sprint days, but I think it mattered
more. This is the day the system became easier to live with.
