# 2026-05-19 -- Day 5

If yesterday was about connecting to the outside world, today was about
making those connections actually behave inside the app.

The headline was not one feature. It was a cluster of integration plumbing
that makes the whole system feel less brittle.

**27 commits.** A lot of them were about the seams between the app and the
services around it.

## What landed

### Proxy configuration became part of the product

The biggest infrastructure change was taking HTTP proxy support seriously.

Proxy settings are now an actual app-level concept instead of a hidden
environment variable ritual. The config is persisted, applied at runtime,
and exposed through the UI. HTTPS proxies and custom CA bundles are part of
the story too.

That matters because integrations should not depend on a clean network
environment. If I am behind a proxy, the app should still know how to talk
out.

### The streaming model got a cleaner boundary

`feat(streaming)!` split run submission from event subscription via
EventSource.

That sounds abstract, but it’s one of those changes that makes the
integration surface easier to reason about. The app now treats sending a run
and listening for events as separate concerns, which makes reconnects and
re-attachment less awkward.

### External integrations got easier to extend

I also widened the integration surface in a few directions:

- The official MCP Registry can be used for discovery.
- External providers and tools can be hot-loaded.
- Native GitHub REST tools landed.
- Environment sync can pull from shell rc files and the Windows registry.

That combination is important. Discovery, loading, and runtime config are
what make an integration feel like part of the system instead of a one-off
hack.

### Onboarding now explains the integration story better

The setup flow was pushed toward integration manifests instead of an empty
shell.

That makes the app easier to introduce to someone else, but it also helps me
when I revisit it later. The app is no longer just "there are tools". It is
"here is how the tools connect."

### A few operational edges got cleaned up

There was still plenty of supporting work around the integrations:

- Tailscale serve recipes were tightened up.
- The macOS launchctl path was modernized.
- Deep link and URL sync fixes reduced the chance of getting lost between
  surfaces.

None of those are glamorous, but they make the integrations feel reachable
in everyday use.

## What I learned

- Integrations are not just auth and API calls; they are config, discovery,
  runtime loading, and docs.
- Splitting responsibilities early makes reconnect and retry logic easier
  later.
- The more external systems the app touches, the more important the seams
  become.

Day 5 was basically a day of turning "can connect" into "can keep working."
