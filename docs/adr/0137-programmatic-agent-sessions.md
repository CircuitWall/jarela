# ADR-0137: Programmatic agent sessions with on-demand SDK runtimes

Status: **Accepted**

Date: 2026-11-28

Related: [ADR-0120](./0120-copilot-sdk-delegate.md) (Copilot SDK delegate),
[ADR-0122](./0122-on-demand-heavy-runtimes.md) (on-demand heavy runtimes),
[ADR-0071](./0071-claude-code-delegation-tool.md) (Claude Code delegation),
[ADR-0087](./0087-delegate-default-full-parity.md) (delegate full-access
parity), [ADR-0121](./0121-optional-tool-and-integration-dependencies.md)

## Context

Jarela already delegates one-shot coding tasks to Claude Code, Codex, and
GitHub Copilot: `claude_delegate` and `codex_delegate` spawn the local CLIs with
stream-json output, and `copilot_delegate` uses `@microsoft/copilot-sdk`. None
of these is a terminal/TUI integration, but each is a **single turn with a job
id**, not a conversation the Jarela agent can steer.

All three providers now publish official programmatic SDKs:

- Claude Code: `@anthropic-ai/claude-agent-sdk` (`query()`, streaming input,
  `canUseTool`, sessions, hooks, MCP, subagents).
- Codex: `@openai/codex-sdk` (`startThread`, `runStreamed`, `resumeThread`,
  structured output).
- GitHub Copilot: `@microsoft/copilot-sdk` (sessions, typed events, permission
  callbacks, abort).

The runtimes are large: roughly 200–550 MB unpacked per platform. Bundling all
three into every install would repeat the problem ADR-0122 solved. A terminal
or PTY is not required for any of them; the TUI is not an automation surface.

## Decision

1. **One `agent_session` tool.** It exposes `start`, `send`, `status`, `close`,
   and `list` actions over a provider-neutral session record. The Jarela agent
   keeps one session id and talks to the selected provider turn by turn.
2. **Native SDKs, loaded on demand.** Each provider adapter resolves its
   official SDK through `requireRuntimePackage` (ADR-0122). Missing packages
   return a structured `DEPENDENCY_MISSING` result naming the
   `runtime:<package>` install target; they do not fail the tool registry or
   the install.
3. **Add the missing catalogue entries.** `@anthropic-ai/claude-agent-sdk` and
   `@openai/codex-sdk` join `@microsoft/copilot-sdk` under **Agent runtimes**,
   with their measured platform sizes and a clear "what still works without
   it" note. The existing delegate tools remain available and unchanged.
4. **Sessions are in-memory and thread-scoped.** A session id is generated by
   Jarela, bound to the owning thread, capped per process, and closable. The
   provider's own session/thread id is captured for resume within the running
   process. No new persistence schema or data-directory layout is introduced;
   an app restart loses the local session handle. Durable session state would
   require a separate persistence ADR.
5. **Safety parity, not a second authority.** `JARELA_TOOL_SAFETY=safe` refuses
   to start a session. Under `mostly_safe` (default) and `bypass`, each
   provider permission request that the adapter receives is approved once and
   recorded in the session record, matching the existing delegates' behaviour
   for an interactive user who approves prompts. The adapter never widens an
   agent's tool permissions; provider-side sandbox and permission modes still
   apply.
6. **No PTY, no terminal emulator, no TUI scraping.** The agent consumes typed
   SDK events and returns a final message; rendering is not part of this
   feature. Claude uses `canUseTool`; Codex uses its sandbox/approval
   configuration; Copilot reuses its typed permission callback.
7. **Existing delegates stay.** `claude_delegate`, `codex_delegate`, and
   `copilot_delegate` remain the one-shot/background paths and the fallback
   when an SDK package is not installed. `agent_session` is for multi-turn
   steering, not a replacement for the delegate job ledger.

## Consequences

- The optional packages are large; installing all three costs roughly 1 GB.
  Each is independently optional and surfaced through the existing Packages
  panel.
- Live SDK behaviour, auth, and provider-side permissions are not covered by
  unit tests. The adapters use injectable seams and fakes; live smoke tests are
  explicit and opt-in.
- In-memory sessions do not survive a restart. The provider session id is
  returned so a future durable-store ADR can resume it; this slice does not
  persist it.
- Claude and Copilot expose per-request permission callbacks; Codex's SDK
  exposes sandbox/approval configuration rather than a live callback, so the
  session record reports the configured mode instead of inventing approvals.
- The tool is agent-facing only: the human user interacts with the Jarela
  agent, not with Claude/Codex/Copilot TUIs.
